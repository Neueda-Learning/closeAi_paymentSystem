## P0 — 严重问题（必修，阻塞后续 AI 模块接入）

### 修复 1：验证逻辑归位 —— 让 `processValidate` 真正执行验证

**问题定位**：`PaymentServiceImpl.createPayment()` 第 53 行在创建时做了全部验证，而 `processValidate()`（第 125-139 行）只做状态转换，没有任何验证。VALIDATED 状态名不副实。

**修改文件**：

- `service/ValidationService.java`
- `service/impl/PaymentServiceImpl.java`

**具体修改**：

1. `ValidationService` 拆分两层验证：

```java
@Service
public class ValidationService {

    private static final Set<String> SUPPORTED_CURRENCIES = Set.of("USD", "EUR", "GBP", "CNY");
    private static final Pattern ACCOUNT_PATTERN = Pattern.compile("^ACC-\\d{3,10}$");

    /** 创建时的基础格式校验（快速失败） */
    public void validateOnCreate(CreatePaymentRequest request) {
        if (request.getSourceAccount().equalsIgnoreCase(request.getDestinationAccount())) {
            throw new BusinessException(ErrorCode.INVALID_ACCOUNT,
                "Source and destination accounts must be different");
        }
    }

    /** validate 阶段的完整业务校验（CREATED → VALIDATED 前执行） */
    public void validateOnTransition(Payment payment) {
        // 账号格式校验
        if (!ACCOUNT_PATTERN.matcher(payment.getSourceAccount()).matches()) {
            throw new BusinessException(ErrorCode.INVALID_ACCOUNT,
                "Invalid source account format: " + payment.getSourceAccount());
        }
        if (!ACCOUNT_PATTERN.matcher(payment.getDestinationAccount()).matches()) {
            throw new BusinessException(ErrorCode.INVALID_ACCOUNT,
                "Invalid destination account format: " + payment.getDestinationAccount());
        }
        // 货币白名单校验
        if (!SUPPORTED_CURRENCIES.contains(payment.getCurrency().toUpperCase())) {
            throw new BusinessException(ErrorCode.INVALID_CURRENCY,
                "Currency " + payment.getCurrency() + " is not supported");
        }
        // 金额边界复核（防止直接写库的脏数据流转）
        if (payment.getAmount().compareTo(BigDecimal.ZERO) <= 0
                || payment.getAmount().compareTo(new BigDecimal("1000000")) > 0) {
            throw new BusinessException(ErrorCode.INVALID_AMOUNT,
                "Amount out of valid range: " + payment.getAmount());
        }
    }
}
```

2. `PaymentServiceImpl` 调整调用位置：

```java
// createPayment 中：只保留基础校验
validationService.validateOnCreate(request);

// processValidate 中：加入完整业务验证，失败则转 FAILED 并记录原因
@Override
@Transactional
public PaymentResponse processValidate(String paymentId) {
    Payment payment = findPaymentById(paymentId);
    PaymentStatus fromStatus = PaymentStatus.fromString(payment.getStatus());
    PaymentStatus toStatus = PaymentStatus.VALIDATED;

    if (!stateMachineService.canTransition(fromStatus, toStatus)) {
        throw new BusinessException(ErrorCode.INVALID_STATUS_TRANSITION,
                "Cannot transition from " + fromStatus + " to " + toStatus);
    }

    // ★ 新增：完整业务验证，验证失败 → 转 FAILED 状态（而非抛异常中断）
    try {
        validationService.validateOnTransition(payment);
    } catch (BusinessException ex) {
        updatePaymentStatus(payment, PaymentStatus.FAILED.name(), ex.getErrorCode().name());
        recordStatusHistory(paymentId, fromStatus.name(), PaymentStatus.FAILED.name(),
                "Validation failed", ex.getErrorCode().name());
        return getPayment(paymentId);
    }

    // ★ AI 风险评估挂载点（Phase 4 在此插入 riskAssessmentService.assess(payment)）

    updatePaymentStatus(payment, toStatus.name(), null);
    recordStatusHistory(paymentId, fromStatus.name(), toStatus.name(), null, null);
    return getPayment(paymentId);
}
```

**验证方法**：构造一笔账号格式非法（如 `XXX-999`）的支付 → 创建成功（CREATED）→ 调 `/validate` → 状态变 FAILED 且 error_code = INVALID_ACCOUNT，history 中有两条记录。

## P1 — 中等问题（第二周修复）

### 修复 4：幂等重复请求返回 200

**位置**：`PaymentController.createPayment()` 永远返回 201，与 README 自相矛盾。

```java
@PostMapping
public ResponseEntity<ApiResponse<PaymentResponse>> createPayment(...) {
    ...
    PaymentResponse response = paymentService.createPayment(request, idempotencyKey);
    // ★ 让 service 告知是否为重复请求
    boolean isDuplicate = paymentService.wasIdempotentHit(idempotencyKey, response.getId());
    HttpStatus status = isDuplicate ? HttpStatus.OK : HttpStatus.CREATED;
    return ResponseEntity.status(status).body(ApiResponse.ok(response));
}
```

实现方式二选一：

- `PaymentService.createPayment` 返回包装对象 `{ payment, isDuplicate }`
- 或在 service 内部比较 `response.getCreatedAt()` 与本次请求时间窗（不推荐，脆弱）

### 修复 5：统一 retry 幂等语义

**位置**：`PaymentServiceImpl.processRetry()` 第 208-212 行。

冲突时抛 409 与 create 返回已有支付语义不一致。改为：幂等键已存在且关联同一 paymentId → 直接返回当前支付状态（200）；关联**不同** paymentId → 才抛 409。

```java
boolean isNew = idempotencyService.checkAndSave(idempotencyKey, paymentId);
if (!isNew) {
    String existingPaymentId = idempotencyService.getExistingPaymentId(idempotencyKey);
    if (existingPaymentId.equals(paymentId)) {
        return getPayment(paymentId);  // 同一支付的重复重试 → 返回当前状态
    }
    throw new BusinessException(ErrorCode.DUPLICATE_PAYMENT,
            "Idempotency key already used for another payment: " + idempotencyKey);
}
```

### 修复 6：send 阶段加入模拟发送

**位置**：`PaymentServiceImpl.processSend()`。

转入 SENT 后模拟网关处理，让 NETWORK_ERROR 真正可触发：

```java
@Override
@Transactional
public PaymentResponse processSend(String paymentId) {
    // ... 现有状态机校验 ...
    updatePaymentStatus(payment, toStatus.name(), null);
    recordStatusHistory(paymentId, fromStatus.name(), toStatus.name(), null, null);

    // ★ 模拟支付网关：20% 概率网络失败
    if (ThreadLocalRandom.current().nextInt(100) < 20) {
        updatePaymentStatus(payment, PaymentStatus.FAILED.name(), ErrorCode.NETWORK_ERROR.name());
        recordStatusHistory(paymentId, toStatus.name(), PaymentStatus.FAILED.name(),
                "Gateway communication failed (simulated)", ErrorCode.NETWORK_ERROR.name());
    }
    return getPayment(paymentId);
}
```

> 注意：随机种子建议在测试 profile 中固定（`payment.gateway.failure-rate=0` 便于测试，`20` 用于演示）。

### 修复 8：通用异常处理器不再泄露内部信息

**位置**：`GlobalExceptionHandler.handleGenericException()`。

```java
@ExceptionHandler(Exception.class)
public ResponseEntity<ApiResponse<Void>> handleGenericException(Exception ex) {
    log.error("Unhandled exception", ex);  // ★ 详细错误只进服务端日志
    ErrorResponse error = ErrorResponse.builder()
            .code(ErrorCode.PROCESSING_ERROR.name())
            .message("Internal server error")  // ★ 对外固定文案
            .build();
    return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(ApiResponse.fail(error));
}

// ★ 新增：缺请求头返回 400 而非 500
@ExceptionHandler(MissingRequestHeaderException.class)
public ResponseEntity<ApiResponse<Void>> handleMissingHeader(MissingRequestHeaderException ex) {
    ErrorResponse error = ErrorResponse.builder()
            .code(ErrorCode.VALIDATION_FAILED.name())
            .message("Required header is missing: " + ex.getHeaderName())
            .build();
    return ResponseEntity.badRequest().body(ApiResponse.fail(error));
}
```
