Our Answer

Four Pillars of Resilience

K

Idempotency Keys

Every payment carries a unique client-generated key. Same key = same result. No duplicates. Ever.

S

Strict State Machine

Payments move through a well-defined lifecycle. Invalid jumps are rejected before they reach the database.

A

Complete Audit Trail

Every status change is recorded — from, to, when, why. Full traceability for debugging and compliance.

AI

AI Risk Detection

Three-layer progressive analysis: rules → statistics → LLM. High-risk transactions are flagged or blocked.

Beyond the Basics

AI-Powered Risk Assessment

Three-layer progressive analysis fires before a payment enters the VALIDATED state.

1

Rule Engine

Required

5 heuristic rules: amount anomaly, unusual time, new payee, velocity spike, high-value threshold.

Catch known patterns in microseconds.

2

Statistical Analysis

Recommended

Z-score deviation + IQR outlier detection against 90-day account history.

Identify unusual behavior without predefined rules.

3

LLM Inference

Optional / Bonus

Calls Claude API for contextual reasoning on borderline cases.

Human-level judgment for ambiguous transactions.

Designed for Failure

Every Step Has a Fallback

We assume things will go wrong. So we plan for it.

T

Transactional Integrity

Every state transition wraps status update + history record in a single DB transaction. If either fails → full rollback. No orphaned states.
E

Exponential Backoff Retry

1s → 2s → 4s → 8s → Retry with same idempotency key. Max 3 attempts before escalating to FAILED.
C

Compensation Actions

SENT state → send fails → FAILED → RETRY → VALIDATED. Failed payments re-enter the pipeline cleanly with a new idempotency key.
A

Audit for Recovery

status_history table is append-only. Every transition records: from → to + timestamp + error_code. Reconstruct any payment's journey at any time.
