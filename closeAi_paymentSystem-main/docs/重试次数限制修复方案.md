# 重试次数限制修复方案

## 一、现状问题

### 当前 processRetry() 逻辑（PaymentServiceImpl 第 232-259 行）

```java
public PaymentResponse processRetry(String paymentId, String idempotencyKey) {
    // 幂等键查重
    String existingForRetry = idempotencyService.findPaymentIdByKey(idempotencyKey);
    if (existingForRetry != null) { ... }

    Payment payment = findPaymentById(paymentId);
    PaymentStatus fromStatus = PaymentStatus.fromString(payment.getStatus());
    PaymentStatus toStatus = PaymentStatus.VALIDATED;

    // 只检查状态机是否允许 FAILED→VALIDATED，不检查重试次数
    if (!stateMachineService.canTransition(fromStatus, toStatus)) { ... }

    updatePaymentStatus(payment, toStatus.name(), null);
    recordStatusHistory(paymentId, fromStatus.name(), toStatus.name(), "Retry attempt", null);
    return getPayment(paymentId);
}
```

### 问题清单

| # | 问题 | 影响 |
|---|------|------|
| 1 | `payments` 表无 `retry_count` 字段 | 无法追踪重试次数 |
| 2 | `PaymentServiceImpl` 无 `MAX_RETRIES` 常量 | 无法设置上限 |
| 3 | `PaymentStatus` 无 EXHAUSTED 状态 | 无法表达"重试耗尽，最终放弃" |
| 4 | 状态机 FAILED→VALIDATED 无次数约束 | 支付可无限重试 |
| 5 | status_history 只写"Retry attempt" | 无法区分第几次重试 |
| 6 | 规范第 126 行明确问"How many times should you retry before marking something as FAILED?" | 当前未回答此问题 |

### 无限重试会导致的实际场景

```
FAILED → retry → VALIDATED → send（20% NETWORK_ERROR）→ FAILED
       → retry → VALIDATED → send（20% NETWORK_ERROR）→ FAILED
       → retry → VALIDATED → send（20% NETWORK_ERROR）→ FAILED
       → ... 无限循环
```

一笔支付在模拟网关下，统计期望约 5 次重试才能成功（每次 80% 成功率，1/0.8 ≈ 1.25 次到 SENT；但实际可能连续碰到 20% 失败 10+ 次）。如果错误原因不是网络而是"余额不足"（INSUFFICIENT_FUNDS），则**永远不可能成功**，重试会无限消耗资源。

## 二、修复方案

### 方案选择：不引入新状态，用 FAILED + retry_count 区分

**为什么不用 EXHAUSTED 新状态？**
- 改动范围最小（不需要新状态枚举、新状态机转换、新前端展示）
- FAILED 已经表达了"失败"语义，retry_count >= MAX 后的 FAILED 只是不能再重试了
- 前端只需在 FAILED 状态的支付上多显示一行"已重试 3 次，无法继续重试"
- ErrorCode 新增 `RETRY_EXHAUSTED` 即可在审计历史中区分"普通失败"和"重试耗尽"

#### 4. PaymentServiceImpl 加 MAX_RETRIES 常量 + 重试次数检查

**PaymentServiceImpl.java**
```java
public class PaymentServiceImpl implements PaymentService {

    private static final int MAX_LIMIT = 100;
    private static final int MAX_RETRIES = 3;  // ★ NEW — 最大重试次数

    // ... 其余字段不变 ...

    @Override
    @Transactional
    public PaymentResponse processRetry(String paymentId, String idempotencyKey) {
        // Idempotency check FIRST
        String existingForRetry = idempotencyService.findPaymentIdByKey(idempotencyKey);
        if (existingForRetry != null) {
            if (existingForRetry.equals(paymentId)) {
                return getPayment(paymentId);
            }
            throw new BusinessException(ErrorCode.DUPLICATE_PAYMENT,
                    "Idempotency key already used for another payment: " + idempotencyKey);
        }

        Payment payment = findPaymentById(paymentId);
        PaymentStatus fromStatus = PaymentStatus.fromString(payment.getStatus());

        // ★ NEW: 检查重试次数上限
        if (payment.getRetryCount() >= MAX_RETRIES) {
            throw new BusinessException(ErrorCode.RETRY_EXHAUSTED,
                    "Payment has been retried " + payment.getRetryCount()
                    + " times (max: " + MAX_RETRIES + ") and cannot be retried further");
        }

        // ★ NEW: 验证状态转换（FAILED → VALIDATED）
        PaymentStatus toStatus = PaymentStatus.VALIDATED;
        if (!stateMachineService.canTransition(fromStatus, toStatus)) {
            throw new BusinessException(ErrorCode.INVALID_STATUS_TRANSITION,
                    "Cannot retry from status " + fromStatus);
        }

        // Save idempotency record for this retry
        idempotencyService.checkAndSave(idempotencyKey, paymentId);

        // ★ NEW: 递增重试次数
        payment.setRetryCount(payment.getRetryCount() + 1);

        updatePaymentStatus(payment, toStatus.name(), null);
        recordStatusHistory(paymentId, fromStatus.name(), toStatus.name(),
                "Retry attempt #" + payment.getRetryCount(), null);  // ★ NEW: 标注第几次

        return getPayment(paymentId);
    }

    // ★ NEW: 当支付因重试耗尽失败时，自动标记为 RETRY_EXHAUSTED
    // 在 processSend / processValidate 中，如果失败且 retryCount >= MAX_RETRIES，
    // error_code 使用 RETRY_EXHAUSTED 替代原来的 NETWORK_ERROR
    @Override
    @Transactional
    public PaymentResponse processSend(String paymentId) {
        Payment payment = findPaymentById(paymentId);
        PaymentStatus fromStatus = PaymentStatus.fromString(payment.getStatus());
        PaymentStatus toStatus = PaymentStatus.SENT;

        if (!stateMachineService.canTransition(fromStatus, toStatus)) {
            throw new BusinessException(ErrorCode.INVALID_STATUS_TRANSITION,
                    "Cannot transition from " + fromStatus + " to " + toStatus);
        }

        updatePaymentStatus(payment, toStatus.name(), null);
        recordStatusHistory(paymentId, fromStatus.name(), toStatus.name(), null, null);

        // Simulated payment gateway: 20% chance of network failure
        if (ThreadLocalRandom.current().nextInt(100) < 20) {
            // ★ NEW: 如果已重试过且 retryCount >= MAX_RETRIES，使用 RETRY_EXHAUSTED
            ErrorCode failCode = ErrorCode.NETWORK_ERROR;
            String failReason = "Gateway communication failed (simulated)";
            if (payment.getRetryCount() != null && payment.getRetryCount() >= MAX_RETRIES) {
                failCode = ErrorCode.RETRY_EXHAUSTED;
                failReason = "Gateway failed after " + payment.getRetryCount() + " retries (max: " + MAX_RETRIES + ")";
            }
            updatePaymentStatus(payment, PaymentStatus.FAILED.name(), failCode.name());
            recordStatusHistory(paymentId, toStatus.name(), PaymentStatus.FAILED.name(),
                    failReason, failCode.name());
        }

        return getPayment(paymentId);
    }

    // ★ NEW: validate 中同样 — 验证失败且 retryCount >= MAX_RETRIES
    @Override
    @Transactional
    public PaymentResponse processValidate(String paymentId) {
        Payment payment = findPaymentById(paymentId);
        PaymentStatus fromStatus = PaymentStatus.fromString(payment.getStatus());
        PaymentStatus toStatus = PaymentStatus.VALIDATED;

        if (!stateMachineService.canTransition(fromStatus, toStatus)) {
            throw new BusinessException(ErrorCode.INVALID_STATUS_TRANSITION,
                    "Cannot transition from " + fromStatus + " to " + toStatus);
        }

        try {
            validationService.validateOnTransition(payment);
        } catch (BusinessException ex) {
            // ★ NEW: 如果 retryCount >= MAX_RETRIES，error_code 用 RETRY_EXHAUSTED
            ErrorCode failCode = ex.getErrorCode();
            if (payment.getRetryCount() != null && payment.getRetryCount() >= MAX_RETRIES) {
                failCode = ErrorCode.RETRY_EXHAUSTED;
            }
            updatePaymentStatus(payment, PaymentStatus.FAILED.name(), failCode.name());
            recordStatusHistory(paymentId, fromStatus.name(), PaymentStatus.FAILED.name(),
                    "Validation failed: " + ex.getMessage(), failCode.name());
            return getPayment(paymentId);
        }

        updatePaymentStatus(payment, toStatus.name(), null);
        recordStatusHistory(paymentId, fromStatus.name(), toStatus.name(), null, null);
        return getPayment(paymentId);
    }
}
```

```java
// ===== Case: retry count exhausted =====

@Test @DisplayName("Retry — succeeds when retryCount < MAX_RETRIES")
void retryWithinLimit() {
    Payment payment = new Payment();
    payment.setId("pay-001");
    payment.setStatus("FAILED");
    payment.setRetryCount(1);  // 第 2 次重试（总共允许 3 次）
    when(paymentMapper.selectById("pay-001")).thenReturn(payment);
    when(idempotencyService.findPaymentIdByKey("retry-key-2")).thenReturn(null);
    when(idempotencyService.checkAndSave("retry-key-2", "pay-001")).thenReturn(true);
    when(paymentMapper.updateById(any())).thenReturn(1);

    PaymentResponse response = paymentService.processRetry("pay-001", "retry-key-2");
    assertEquals("VALIDATED", response.getStatus());
    assertEquals(2, response.getRetryCount());
}

@Test @DisplayName("Retry — fails when retryCount >= MAX_RETRIES")
void retryExhausted() {
    Payment payment = new Payment();
    payment.setId("pay-001");
    payment.setStatus("FAILED");
    payment.setRetryCount(3);  // 已重试 3 次，达到上限
    when(paymentMapper.selectById("pay-001")).thenReturn(payment);

    BusinessException ex = assertThrows(BusinessException.class,
            () -> paymentService.processRetry("pay-001", "retry-key-final"));
    assertEquals(ErrorCode.RETRY_EXHAUSTED, ex.getErrorCode());
    assertTrue(ex.getMessage().contains("retried 3 times"));
}

@Test @DisplayName("Retry — increments retryCount correctly across multiple retries")
void retryCountIncrement() {
    // 第 1 次重试：retryCount 0 → 1
    Payment payment1 = new Payment();
    payment1.setId("pay-001");
    payment1.setStatus("FAILED");
    payment1.setRetryCount(0);
    payment1.setVersion(0);
    when(paymentMapper.selectById("pay-001")).thenReturn(payment1);
    when(idempotencyService.findPaymentIdByKey("retry-1")).thenReturn(null);
    when(idempotencyService.checkAndSave("retry-1", "pay-001")).thenReturn(true);
    when(paymentMapper.updateById(any())).thenReturn(1);

    PaymentResponse resp1 = paymentService.processRetry("pay-001", "retry-1");
    assertEquals(1, resp1.getRetryCount());
}
```

## 三、MAX_RETRIES 值的选择建议

| MAX_RETRIES | 适用场景 | 说明 |
|-------------|---------|------|
| 3 | **推荐** | 市面主流做法（Stripe 默认 3 次、Adyen 重试策略最多 3 次自动重试），足够覆盖网络抖动场景 |
| 5 | 保守策略 | 适用于容错要求高、网络环境不稳定的场景，但存储开销更大 |
| 1 | 严格策略 | 只允许重试一次，适用于金融监管严格的场景（失败必须人工介入） |

**本项目建议 MAX_RETRIES = 3**，理由：
- 20% 模拟失败率下，3 次重试的成功概率 = 1 - 0.2^4 ≈ 99.84%（即连续 4 次 20% 失败的概率仅 0.16%）
- 与 Stripe 等主流系统对齐，演示时有说服力
- 足够覆盖真实网络故障场景（1-2 次重试通常就能恢复）
